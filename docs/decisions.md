| 2026-11-15 | Dependabot exception to the commit identity rule | Owner decision (option a). Dependabot commits pass the identity checks (`validate` on PRs, `Identity (branch push)`) only when ALL hold: branch `dependabot/**`, PR author and the pushing actor (Validate) or the pusher (branch push) `dependabot[bot]`; every commit of the range is Dependabot's (author `dependabot[bot]`, committer GitHub `web-flow`, as Dependabot really commits); the GitHub API confirms each commit (`verification.verified`, author login `dependabot[bot]`, committer login `web-flow`); each commit only modifies the root `package.json`/`package-lock.json`, a workspace `package.json` or `uses: owner/repo@<sha>` lines in `.github/workflows/*.yml`. Lockfile-only updates (transitive dependencies) get no exception and stay red; they need a maintainer commit. Everything else stays strict; `dependabot[bot]` is not on the e-mail allowlist. Code: `scripts/lib/dependabot-exemption.mjs`. |
| 2026-11-16 | Data licence in API v1 stays fixed | Owner decision. In the v1 OpenAPI `Meta` schema `license.name`, `license.spdx` and `license.url` stay `const` (CC BY 4.0). A change of the data licence would come with a new path `/api/v2/`; what happens to `/api/v1/` then is decided together with that change. Reason: v1 changes only additively, and clients may rely on the licence of what they fetch. The alternative, relaxing the consts to `type: string` with an `enum`, would itself widen v1 values that clients validate against. |
